# CoBlocks 4.0.0 — CI modernization + Block API v3 migration (attempt 3)

**Date:** 2026-07-13
**Branch:** `release/4.0.0` (off `master`; the integration branch for CoBlocks 4.0.0)
**Fork:** `ncimbaljevic/coblocks`
**Supersedes:** `docs/superpowers/specs/2026-07-11-coblocks-4.0.0-modernization.md` (keeps its branch model; changes the CI model from *automatic-but-filtered* to *on-demand*, and forbids stacked PRs).

## Problem

Two prior attempts to ship the WP 7.0 / Node 24 / React 18 + Block-API-v3 modernization
were bulk-closed (reset) rather than merged. A CI/post-mortem of the closed PRs (#1–#28
on the fork) found the failures were **structural, not code-quality**:

1. **A 14-deep stacked-PR chain hid the work from CI.** Each block PR was based on the
   previous branch; only the root targeted a mainline branch. Path-filtered workflows
   only trigger on PRs into `master`/`release/4.0.0`, so **13 of 14 PRs got zero CI runs
   in each attempt** — the entire v3 migration was never validated in Actions.
2. **The one PR that ran CI was a red wall — an *environment* failure.** Foundation PR #15
   ran 54 checks → 6 pass / 42 fail / 2 cancelled. 36 failures were E2E that **died at
   `yarn install`/build; Cypress never ran** (no video produced). Two WP 7.0 PHPUnit jobs
   hung 15m26s then were cancelled (no `timeout-minutes` anywhere). PR #1's body claimed
   local green while CI was 31/8 red — the local-vs-Actions gap was never closed.
3. **The fan-out is a storm.** A single block-bundle PR to `release/4.0.0` triggers up to
   **~199 jobs** (legacy PRs to `master`: up to ~636). The shape is
   `matrix-combos × one-job-per-spec`: every Cypress spec gets its own job that boots
   wp-env + rebuilds the plugin + runs one spec. Path filters gate *whether* E2E runs, not
   *how wide*. `test-wp-next-v4.yml` has **no** path filter and re-runs the E2E matrix on
   every PR.

## Goals

- **No action storm.** A routine PR triggers a handful of fast, deterministic jobs
  (lint + Jest + one PHP-unit combo). The expensive browser/matrix E2E runs **only
  on-demand**.
- **Every chunk is independently CI-validated.** No stacked chain: every PR targets
  `release/4.0.0` directly, gets its own CI, and can merge in any order.
- **The foundation is proven green in Actions once** before any block work stacks on it.
- **Small, single-concern chunks** that are easy to read and revert without cascading.

## Non-goals

- Touching `master` / the legacy v3 CI during the effort (only at ship time).
- Migrating Cypress → Playwright (keep Cypress ^13; a full spec rewrite is out of scope).
- One mega-PR; deep stacked chains; empty (no-change) dimension PRs.

## Decisions (locked)

- **CI strategy:** on-demand E2E. Per-PR auto CI = fast lint + Jest + one PHP-unit combo.
  The full E2E / WP×PHP gamut runs only via `workflow_dispatch` (or a `run-e2e` PR label).
- **Landing model:** independent PRs into `release/4.0.0`, never stacked; 1–3 open at a time.
- **Merge gate:** auto lint+Jest per chunk; targeted **local** Cypress for interactive-edit
  blocks; one full local E2E sweep before shipping.
- **Verification is run locally by the agent** (wp-env + Cypress + Jest via Bash).
- **Keep Cypress 13; keep React 18.3.1; WP 7.0 tilde-pinned `@wordpress/*`; Node 24.**

## Stack targets (from the completed, verified upgrade on `feat/*`)

- **Node 24** (`.nvmrc`), `engines.node >=20`.
- **WordPress 7.0** package set — every `@wordpress/*` tilde-pinned to its `wp-7.0`
  dist-tag, forced tree-wide via `resolutions` (kills duplicate 7.1-trunk copies).
  `Tested up to: 7.0`, `Requires at least: 6.3`.
- **React 18.3.1** (WP 7.0 core still ships React 18; CoBlocks externalizes `wp.element`).
- **Build:** wp-scripts 31 / webpack (`npm run build`); Gruntfile **retained** for ancillary i18n/zip tasks (only the build moved off grunt); sass-loader `loadPaths` + `@use` fixes.
- **PHP:** WPCS 2→3 (+ phpcs.xml rewrite), phpcs 3.13, mozart 0.7.1, phpunit ^9.6,
  Yoast polyfills ^1.1; `Requires PHP: 7.4`.
- **E2E:** Cypress ^13, WP 7.0 / Cypress 13 harness fixes (see E2E-harness foundation PR).

## Architecture: branch & PR model

```
master (v3, untouched)
  └── release/4.0.0                      ← integration branch; every v4 PR targets this
        ├── Phase 0:  v4/ci-oncall       (workflows only — 0 test jobs)
        ├── Phase 1:  v4/f-build, v4/f-php, v4/f-js, v4/f-css, v4/f-e2e-harness
        │             (each independent, one concern; foundation must go green once)
        └── Phase 2:  v4/blocks-1 … v4/blocks-13  (independent, NOT stacked; risk order)
```

Every `v4/*` branch is cut from the **current** `release/4.0.0` tip and PR'd straight into
it. A foundation fix never invalidates descendants because nothing is stacked.

## CI redesign (Phase 0 — the on-demand model)

A **workflows-only PR** (`v4/ci-oncall`) that touches only `.github/workflows/**`. Because
the `-v4` path filters key on `**.php` / `**.js` / `**.scss` / `src/blocks/**`, a
workflow-only change matches **none** of them → **triggers zero test jobs**. Safest possible
first PR, and it makes everything after cheap.

Changes to the `-v4` workflows:

1. **E2E → on-demand + collapsed.** `test-e2e-v4.yml` / `test-e2e-cypress-v4.yml`:
   - Trigger becomes `workflow_dispatch` (inputs: WP version, optional spec filter) **+**
     `pull_request` guarded by `if: contains(github.event.pull_request.labels.*.name, 'run-e2e')`.
     Remove the unconditional `pull_request`/`push` E2E triggers.
   - **Collapse the per-spec fan-out:** replace `matrix: spec` (one job per spec) with a
     single job per WP/PHP combo that runs `cypress run` over the whole selected spec set
     (one wp-env boot, one build). Job count when fired: **3 combos** (was ~144).
   - Add `timeout-minutes: 30` to every job; keep `concurrency` cancel-in-progress.
2. **`test-wp-next-v4.yml`:** remove its unconditional PR E2E fan-out; fold WP-next in as a
   `workflow_dispatch` combo (and/or a nightly `schedule`). No E2E on ordinary PRs.
3. **Auto per-PR lanes (kept, path-filtered, cheap):**
   - `validation-coding-standards-v4.yml` — php/css/js lint (fast).
   - `test-javascript-v4.yml` — Jest (1 job).
   - `test-php-v4.yml` — **reduce matrix from 3 combos to 1** (WP 7.0 + PHP 8.4) for the
     auto gate; the full 3-combo PHP matrix moves to the on-demand gamut.
4. **Bump action versions to latest** across all `-v4` workflows: `actions/checkout@v5`,
   `actions/setup-node@v5` (Node 24), `actions/upload-artifact@v4` (current), etc. — kills
   the Node-20 deprecation warnings the runners now emit.
5. Add an optional `workflow_dispatch` **"full validation"** entrypoint that runs the whole
   gamut (E2E 3 combos + PHP 3 combos) for milestone/ship checks.

### Resulting job counts (auto, per PR)

| PR kind | Jobs auto-triggered |
|---|---|
| Phase 0 (workflows only) | **0** |
| Foundation PHP PR | phpunit(1) + lint(≤3) ≈ **4** |
| Foundation JS PR | Jest(1) + lint(≤3) ≈ **4** |
| Block bundle PR (js+scss) | Jest(1) + lint(≤3) ≈ **4** |
| **On-demand E2E gamut (when fired)** | **3** (one per WP/PHP combo) + setup |

Whole migration ≈ **under ~70 fast jobs total**, spread over time, none of them the flaky
browser E2E — versus ~199 on a *single* bundle PR under the old shape.

## Phase 2 — block bundles (v3 migration), risk-ordered

56 registered blocks across 13 `blocks-{n}.js` bundles. On `release/4.0.0` today: 51 v1 /
6 v2 / 0 v3. The finished v3 work exists on `feat/block-api-v3-part{1..13}` (1:1 with
bundles); each `v4/blocks-N` branch is cut from the current `release/4.0.0` and carries only
that bundle's changes (apiVersion 3 + `useBlockProps` + deprecation for static blocks +
per-block compat + that bundle's SCSS reformat + Cypress spec updates).

**The v3 recipe (per static block):** `apiVersion:3` in `block.json`; `useBlockProps()` on
the edit root; `useBlockProps.save()` on the save root; prepend a verbatim copy of the old
v1 save as `deprecated.js` entry 0. Dynamic blocks (`save:()=>null`) need only
apiVersion + `useBlockProps` in edit — **no deprecation**. (Mechanism: a deprecation that
omits `apiVersion` registers as v1 and re-applies the auto-class filter, so v3 save output
is byte-identical → snapshots unchanged.)

**Split by burden:** ~35 static blocks (deprecation entry required) / 21 dynamic
(apiVersion bump only — the whole 13-block form bundle is dynamic).

**Order — cheapest/safest → riskiest** (each gets auto lint+Jest; Tier C + iframe blocks
also get a local Cypress run of their specs before merge):

- **Tier A (dynamic / server-rendered, no deprecation):**
  `blocks-3` (form + 12 fields), `blocks-8` (icon), `blocks-10` (gallery-stacked,
  shape-divider, share, social-profiles), `blocks-11` (post-carousel*, posts).
- **Tier B (static, clean snapshots):**
  `blocks-1` (accordion, alert, author, buttons [class→functional], gallery-carousel),
  `blocks-7` (gallery-offset, media-card, opentable), `blocks-9` (gif, gist, hero*,
  highlight), `blocks-12` (map), `blocks-13` (counter + **unbundled testimonials**).
- **Tier C (known-risky / previously-failing E2E / iframe / split — always local E2E):**
  `blocks-2` (dynamic-separator‡, events, faq, features, row/column* child),
  `blocks-6` (pricing-table, **row parent***, services),
  `blocks-4` (click-to-tweet‡, food-and-drinks, gallery-collage [GutterWrapper double-class fix]),
  `blocks-5` (**gallery-masonry** [moxie-upload fix‡], logos).

`*` = iframe-edit fix (hero, row/column, post-carousel); `‡` = previously-failing E2E.

**Coordination notes:** `row` is split — child `row/column` in `blocks-2`, parent `row` in
`blocks-6` (different files → independent PRs, no conflict); land them close together and
run row+column E2E after both. `testimonials` (+child) is in no bundle — migrate it with
`blocks-13`.

## Phase 3 — ship

1. Full **local** E2E sweep (all 47 specs) + one deliberate manual CI E2E+PHP gamut →
   confirm green in Actions.
2. Bump version to **4.0.0**, update `readme.txt`/changelog, `Tested up to: 7.0`.
3. **Promote `-v4` workflows to canonical:** retarget them to `master`, delete the legacy
   grunt-based workflows. (This is the "CI/CD upgraded to latest versions" end-state.)
4. Merge `release/4.0.0` → `master`.

## Definition of done (per chunk)

- **Foundation PR:** its auto lane green in Actions; re-sliced tree matches the known-good
  `feat/*` state for its concern.
- **Block bundle PR:** auto lint+Jest green (snapshots identical = save output byte-for-byte
  unchanged); Tier C / iframe bundles additionally green on a local Cypress run of their specs.
- **Foundation milestone:** one green CI gamut (E2E + PHP) in Actions before Phase 2 begins.
- **Ship:** full local sweep green; version bumped; workflows promoted; merged to `master`.

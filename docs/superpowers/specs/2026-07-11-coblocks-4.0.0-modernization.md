# CoBlocks 4.0.0 modernization — decomposed, non-blocking PR strategy

## Problem

The WP 7.0 / Node 24 / React 18 / Block-API-v3 modernization was staged on one
branch (`feat/general-updates` + a stacked v3 migration). Because dependencies,
block code, tests and lint fixes were all entangled on a single branch, **every
push ran the full CI surface (~170–200 jobs)** — the E2E spec matrix fanned out
across every changed block, jobs timed out, and slicing blocks back out broke the
base (reverting a block re-introduced the WPCS/stylelint violations the upgrade
had fixed).

## Goals

- **Minimal, easy-to-understand PRs** — each PR touches one concern.
- **Do not block the main flow** — v4 work lives on `release/4.0.0`; `master`
  (v3) development and its CI are untouched.
- **No 200-action storm** — each PR runs only the checks its changes touch.

## Structure

```
master (v3, untouched)
  └── release/4.0.0            ← integration branch for CoBlocks 4.0.0
        ├── foundation PRs (by concern / test group)
        └── block-bundle PRs (v3 apiVersion migration, by blocks-{n}.js group)
```

- **`release/4.0.0`** is branched off `master` and is the target of every v4 PR.
  It only merges to `master` when 4.0.0 ships, so nothing here blocks v3.

### CI: v4 workflows, path-filtered

Clone the test workflows to **`*-v4.yml`** variants that:
1. Trigger on `pull_request` with `base: release/4.0.0` (and pushes to it) — so
   the existing (master-gated) v3 workflows never fire on v4 PRs, and vice-versa.
2. Carry `paths:` filters so **each PR only runs the checks its files touch**:
   - `test-php-v4` → `**/*.php`, `composer.*`, `phpcs.xml*`
   - `test-javascript-v4` → `**/*.js`, `**/*.json`, jest config (excluding php/scss)
   - `test-css-v4` → `**/*.scss`, `.stylelintrc*`
   - `test-e2e-v4` → `src/(blocks|extensions|components|block-styles)/**`, cypress
3. Keep the fixes already proven this cycle: E2E changed-files diff vs the PR
   **base** branch (not `master`); `concurrency` cancel-in-progress; `npm run
   build`; wp-env 9264/9281 ports; plugin activation.

Result: a PHP-only PR runs only PHP; a stylelint-only PR runs only CSS; a block
group's JS/edit PR runs JS + its E2E specs. **If a group has no change for a
dimension, that dimension has no PR.**

### Foundation PRs (by test group / concern)

Each is independently green and small:

| PR | Concern | Touches | Checks |
|----|---------|---------|--------|
| F1 | v4 CI workflows | `.github/workflows/*-v4.yml` | (meta) |
| F2 | Build tooling | `.nvmrc`, webpack, wp-scripts, build deps, drop grunt | JS |
| F3 | PHP / WPCS 3 | `composer.*`, `phpcs.xml`, `includes/**.php`, block `index.php` fixes | PHP |
| F4 | JS deps (WP7/React18) | `package.json`, jest config, shared components | JS |
| F5 | stylelint 16 + SCSS | `.stylelintrc`, all `**/*.scss` reformat | CSS |
| F6 | E2E (Cypress 13 / WP7) | `cypress.config.js`, `helpers.js`, extension/component specs | E2E |

### Block-bundle PRs (v3 migration)

The 13 `blocks-{n}.js` groups, one PR each, stacked after the foundation. Each
carries only that bundle's blocks (apiVersion 3 + deprecation + any per-block
compat), so each triggers only its own E2E specs.

## Sourcing

The modernization is already implemented on `feat/general-updates` and the v3
work. Re-slice — do not rewrite — onto `release/4.0.0` by concern (foundation)
and by bundle (blocks), verifying the cumulative tree matches the known-good
combined state.

## Non-goals

- Touching `master` / v3 CI.
- One mega-PR. Empty (no-change) dimension PRs.

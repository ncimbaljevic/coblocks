# CoBlocks 4.0.0 — CI modernization + Block API v3 migration — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Modernize the CoBlocks CI/CD pipeline to the latest versions and migrate all 56 blocks to Block API v3, landing everything on `release/4.0.0` as small, independently-CI-validated chunks that never trigger a job storm.

**Architecture:** Every chunk is an independent PR into `release/4.0.0` — **never stacked** (the #1 cause of both prior failures: stacking left 13/14 PRs untested). CI is redesigned so per-PR checks are fast and deterministic (lint + Jest + one PHP-unit combo); the expensive browser/matrix E2E gamut runs **on-demand only** (`workflow_dispatch` or a `run-e2e` PR label), with the per-spec fan-out collapsed to one job per WP/PHP combo. The completed, verified work is **re-sliced** (not rewritten) from known-good refs: non-block foundation from commit `da54aa7c`, all block v3 work from `feat/block-api-v3-part13`.

**Tech Stack:** WordPress 7.0 (`@wordpress/*` tilde-pinned to the `wp-7.0` dist-tag, forced tree-wide via `resolutions`), React 18.3.1, Node 24, wp-scripts 31 / webpack build, WPCS 3 / phpcs 3.13 / PHPUnit 9.6, Cypress ^13, GitHub Actions.

## Global Constraints

- **No stacked PRs.** Every branch is cut fresh from the current `release/4.0.0` tip and PR'd straight into it. Never base a PR on another `v4/*` branch. Never target `master` (except the final Phase 3 merge).
- **On-demand E2E.** Per-PR auto CI = lint + Jest + one PHP-unit combo only. The E2E / WP×PHP gamut runs only via `workflow_dispatch` or the `run-e2e` PR label. Bundle PRs do **not** auto-run E2E; risky bundles are E2E-verified **locally**.
- **Re-slice, do not rewrite.** Non-block foundation ← commit `da54aa7c`. All block v3 work ← `feat/block-api-v3-part13`. Verify the sliced tree matches the known-good state; never hand-edit the migrated block code.
- **Version pins (verbatim):** Node 24 (`.nvmrc`), `engines.node >=20`. `@wordpress/*` tilde-pinned to `wp-7.0`. React `18.3.1`. Cypress `^13`. WPCS `3`, phpcs `3.13`, PHPUnit `^9.6`, mozart `0.7.1`. `Tested up to: 7.0`, `Requires at least: 6.3`, `Requires PHP: 7.4`.
- **Verification baselines (state as Expected output):** Jest `~589 pass / 341 snapshots` — the **341 snapshot count must stay identical** (proves save output byte-unchanged). `npm run build` clean (only pre-existing Sass `@import` deprecation warnings). eslint/stylelint/phpcs 0 errors. PHPUnit (local wp-env) `184 tests, 3 skips`. Cypress (local, WP 7.0.1 on `:8889`, theme `twentytwentyfive`, plugin `coblocks` active): target `≥46/47` specs green; run with a Bash timeout `≥300000`.
- **Husky:** run `corepack enable` once before the first commit each session (puts yarn on PATH; JS-touching commits fail otherwise).
- **Commits** end with a trailing line: `Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>`.
- **Jest workers:** cap with `--maxWorkers=2` to avoid RAM exhaustion.

## Execution order & gating

1. **Phase 0 first** (`v4/ci-oncall`) — workflows-only, triggers **zero** test jobs; makes everything after cheap.
2. **Phase 1 foundation** — land **`v4/f-js` first** (it owns `package.json`/`yarn.lock`); then cut `v4/f-php`, `v4/f-build`, `v4/f-css`, `v4/f-e2e-harness` from the **updated** `release/4.0.0` and land them. Finish with the **Foundation green gate** — one green on-demand CI gamut in Actions **before any Phase 2 work** (the attempt-1/2 lesson: trust CI, not just local).
3. **Phase 2 bundles** — 13 independent PRs in the given **risk order** (cheapest/dynamic first, riskiest/iframe last). Keep only **1–3 open at a time**. Tier-C/iframe bundles get a local Cypress run before merge.
4. **Phase 3 ship** — full sweep, version bump, promote workflows to canonical, merge to `master`.

```yaml
name: Test / E2E Runner [v4]

on:
  # Manual gamut / targeted run.
  workflow_dispatch:
    inputs:
      wpVersion:
        description: 'WordPress core ref (e.g. WordPress/WordPress#7.0)'
        required: false
        default: 'WordPress/WordPress#7.0'
        type: string
      phpVersion:
        description: 'PHP version (e.g. 8.4)'
        required: false
        default: '8.4'
        type: string
      specFilter:
        description: 'Optional Cypress spec glob (empty = all specs)'
        required: false
        default: ''
        type: string
  # On-demand on PRs: runs ONLY when the `run-e2e` label is present. The path
  # filter means a workflows-only PR creates no run at all; the `labeled` type
  # lets applying the label to an existing (src-touching) PR start a run.
  pull_request:
    branches: [ release/4.0.0 ]
    types: [ opened, synchronize, reopened, labeled ]
    paths:
      - 'src/blocks/**'
      - 'src/extensions/**'
      - 'src/components/**'
      - 'src/block-styles/**'
      - '.dev/tests/cypress/**'
      - 'cypress.config.js'

# Cancel superseded runs: a new push to the same ref cancels the previous
# still-running run instead of stacking a fresh fan-out on top of it.
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  chrome_e2e:
    name: E2E - Cypress (on-demand)
    # Manual dispatch, or a PR that carries the `run-e2e` label.
    if: >
      github.event_name == 'workflow_dispatch' ||
      contains(github.event.pull_request.labels.*.name, 'run-e2e')
    uses: ./.github/workflows/test-e2e-cypress-v4.yml
    with:
      wpVersion: ${{ github.event_name == 'workflow_dispatch' && inputs.wpVersion || 'WordPress/WordPress#7.0' }}
      phpVersion: ${{ github.event_name == 'workflow_dispatch' && inputs.phpVersion || '8.4' }}
      specFilter: ${{ github.event_name == 'workflow_dispatch' && inputs.specFilter || '' }}
      theme: ""
```
